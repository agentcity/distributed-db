# SQL P0 поверх транзакционного KV

## Проблема

Второй продукт — SQL — должен читать/писать строки через KV-транзакции,
а не через отдельную БД. Нужен минимальный, но честный слой: каталог,
кодирование строк, parser, executor и сетевой вход.

## Требования

- AST/lexer/parser подмножества PostgreSQL: CREATE/DROP TABLE, INSERT,
  SELECT (projection, WHERE по PK, LIMIT), UPDATE, DELETE.
- Каталог и строки в KV: `0x01|table → schema`, `0x02|tableID|pk → row`.
- PK INT/TEXT с order-preserving encoding.
- Executor на транзакциях KV: каждая команда — Begin/Commit, rollback при ошибке.
- HTTP `POST /v1/sql` + `GET /health`, `cmd/sqlsrv`.
- E2E: CREATE/INSERT/SELECT/UPDATE/DELETE на реальном KV-узле.

## Критерии приёмки

- [x] Parser и AST для P0-подмножества.
- [x] Каталог/row encoding, PK INT/TEXT.
- [x] Executor через KV-транзакции.
- [x] HTTP-сервер SQL.
- [x] E2E на реальном KV и 3-узловой failover с kill лидера.
- [x] Secondary indexes: CREATE/DROP INDEX, WHERE по indexed-колонке.
- [x] Multi-row UPDATE/DELETE по indexed WHERE.
- [x] Агрегаты COUNT/SUM/AVG/MIN/MAX.
- [x] GROUP BY для агрегатов.
- [ ] JOIN, aggregates, pgwire — вне P0.
